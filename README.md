# 📦 Pack Analytics

Streamlit-сайт для аналізу зміни пакування. Український інтерфейс, завантаження двох Excel-файлів, демонстраційні дані, погодинний графік, усі таблиці та завантаження `Pack_report.xlsx`.

## Швидкий запуск

Рекомендовано Python 3.12.

```bash
python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

На старті відкривається демонстрація з вигаданими даними 12 операторів. У боковій панелі можна перемикати денну/нічну та продовжену зміну. Для робочих даних виберіть «Мої Excel-файли», завантажте обидва файли й натисніть «Сформувати звіт».

## Завантаження на GitHub і публікація

1. Створіть порожній репозиторій GitHub.
2. Завантажте **вміст цієї папки** в корінь репозиторію, включно з прихованими папками `.streamlit` і `.github`. Не завантажуйте архів як єдиний файл.
3. На [Streamlit Community Cloud](https://share.streamlit.io/) підключіть GitHub та створіть застосунок із цього репозиторію.
4. Вкажіть головний файл `app.py`. В Advanced settings виберіть Python 3.12.
5. Запустіть Deploy. Залежності встановлюються з `requirements.txt`.

Або завантажте через Git із папки проєкту:

```bash
git init
git add .
git commit -m "Add packing analytics Streamlit app"
git branch -M main
git remote add origin https://github.com/YOUR_USER/YOUR_REPOSITORY.git
git push -u origin main
```

Офіційні інструкції: [залежності Streamlit Community Cloud](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/app-dependencies).

GitHub зберігає код; Python-застосунок запускається на Streamlit Community Cloud або власному сервері. GitHub Pages не запускає Streamlit.

## Вхідні дані

З кожного `.xlsx` читається перший аркуш. Завантажуйте одну зміну.

| Файл | Обов’язкові колонки |
|---|---|
| Операції | `Package No.`, `Item quantity classification name`, `Operator`, `Packing station`, `Operation time`, `Quantity of scanned` |
| Працівники | `Employee ID`, `Create time` |

`Operator` містить ID у дужках, наприклад `Оператор (1001)`. `Employee ID` у довіднику має бути числовим. Значення `Single product` визначає Single; решта — Multi відповідно до оригіналу. Приклади обох файлів можна скачати у вкладці «Про звіт» демонстрації.

## Збереження логіки

`reference/original.py` — незмінна копія наданого коду. Не використовується вебзастосунком.

`packing/calculations.py` містить ті самі обчислювальні оператори в тому самому порядку. `get_status` перенесено всередину функції розрахунку, щоб дата була локальною для кожного виклику. Вхідні DataFrame копіюються; діагностичні `print` прибрано. Читання файлів і Excel-експорт винесено окремо, жорстко задані імена файлів замінено на завантаження та буфер пам’яті.

Не змінено пороги 15/100/200, норми 120/260/315, коефіцієнти стажу, перерви, останні 15 хвилин, правила визначення зміни, групування, HC, UPH, Rate, Unknown і Day1. Стаж, як і раніше, обчислюється від поточної дати сервера, а не від дати операцій.

Збережено також особливості оригіналу: різні правила групування для різних звітів, назву `shape`, рядок `Manual single`, фіксовані координати таблиць Excel. Якщо ліній багато, фіксовані блоки на аркуші By Line можуть перекриватися — координати навмисно не змінювалися. На сайті таблиці показані окремо.

Алгоритм не адаптовано для порожньої зміни, файлів лише з Single або лише з Multi чи інших наборів, які не підтримував оригінал. У разі помилки сайт показує повідомлення і технічні деталі. Повторні ID у довіднику можуть дублювати операції під час merge; сайт попереджає, але не змінює дані. Пропуски залишаються пропусками.

Графік створено з готового `line_report` без повторного підсумкового рядка `Manual single`. KPI беруться з готової Statistics. Це лише візуалізація наявних результатів.

## Структура

```text
app.py                      # Інтерфейс
packing/calculations.py     # Незмінні обчислення в ізольованій функції
packing/excel.py            # Початкові форматування та експорт
packing/inputs.py           # Читання файлів, перевірки, повідомлення
packing/demo.py             # Вигадані дані
reference/original.py       # Оригінал для звіряння
.streamlit/config.toml      # Тема й обмеження завантаження
.github/workflows/tests.yml # Перевірки після push / pull request
tests/                      # Порівняння з оригіналом і перевірка UI
```

## Перевірки

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Тести порівнюють усі результуючі таблиці та значення/стилі всіх клітинок Excel з виконанням оригінального скрипту на чотирьох сценаріях: денна, нічна, продовжена денна та продовжена нічна зміна. Окрема AST-перевірка підтверджує незмінність обчислювальних операторів і трьох допоміжних функцій. Streamlit AppTest перевіряє демонстрацію, перемикачі та порожній стан завантаження.

Перевірки виконуються на синтетичних даних: реальні вхідні Excel-файли не були надані. Дані та сформований Excel живуть у пам’яті поточної сесії, без спільного кешу або запису робочих файлів на диск. Робочі `.xlsx` виключено з Git.
